2. 6-Gate Mechanical Python Verification

One command runs six un-gameable checks: formatting, monotonic lint/type/secret ratchet, architecture import boundaries, public-seam coverage, AST anti-tampering test lock, and AST mutation testing.

python scripts/check.py
Technical Details — All 6 Gates & Anti-Cheat Rules
#GateWhat It Enforces
1ruff format --checkZero formatting drift across src/, tests/, tests_tooling/, scripts/.
2scripts/ratchet.pyRuff + pyright --strict (with active --pythonpath) + bans # noqa / # type: ignore + bans direct SDK imports + secret/token scan. Baseline only shrinks.
3import-linterForbids app.processors from importing third-party SDKs directly (must go through app.adapters).
4pytest --cov=srcBehavioral public-seam replay tests + Hypothesis fuzzing + JSON coverage report.
5scripts/test_guard.pyAST-compares tests/ against main: blocks deleting/renaming tests, lowering assert counts, adding skip/xfail/assert True, editing historical fixtures, or dropping coverage below coverage-baseline.json.
6scripts/mutation_check.pyInjects real logic & fail-closed bugs into an isolated temp copy (PYTHONDONTWRITEBYTECODE=1) and requires >= 85% mutant kill rate.

Also includes local git hooks via scripts/branch_guard.py (blocks committing src/ directly on main) and 11 adversarial self-tests in tests_tooling/test_workflow_gates.py.

3. Hypothesis Property-Based Fuzzing

Acts like an automated chaos monkey inside pytest: generates 50 to 300 weird, unexpected inputs every run, checks universal fail-closed invariants, and shrinks any crash to the tiniest failing reproducer.

HYPOTHESIS_PROFILE=deep python scripts/check.py
Technical Details — Profiles & Strict-Mode Pattern
  • default profile (CI & normal runs): max_examples=50, derandomize=True, deadline=None — fast, reproducible, and container-safe inside Docker.
  • deep profile (major parser refactors): max_examples=300, randomized exploration, deadline=None.
  • Strict Ruff/Pyright pattern: Bundle strategy fields into a @dataclass(frozen=True) with st.builds(...) so tests stay at 1 parameter (zero PLR0913/PLR0917 warnings and zero # type: ignore).
  • Agent instruction: Both CODING_STANDARDS.md and .sandcastle/implement-prompt.md require a @given(...) fail-closed test whenever a parser or decision rule is added or refactored.

5. Level 1 Autonomous Factory & Real-Time DriftWatchdog

Picks unblocked tickets, spawns isolated Docker containers with Codex, monitors every tool call in real time for thrashing or runaway diffs, auto-splits oversized tickets once, verifies all 6 gates, and runs a fresh-context Adversarial Reviewer before merging.

npm --prefix .sandcastle run factory
Technical Details — Hard Caps, Drift Tripwires & Auto-Split
  • Outer caps: MAX_OUTER_CYCLES=6, MAX_PARALLEL=2, MAX_IMPLEMENT_ITERATIONS=4, MAX_VERIFY_RETRIES=2, MAX_REVIEW_ROUNDS=2, MAX_AUTO_SPLITS=1.
  • Live AbortController tripwires (drift-watchdog.ts):
    • Wall-clock cap: DRIFT_MAX_MINUTES=20
    • Total tool-call cap: DRIFT_MAX_TOOL_CALLS=45
    • Thrash detector: DRIFT_MAX_REPEATED_TOOLS=6 identical tool calls
    • Post-run blast radius: DRIFT_MAX_DIFF_LINES=300, DRIFT_MAX_DIFF_FILES=6
    • Context-rot guard: DRIFT_MAX_CONTEXT_RATIO=0.75
  • 1-shot remediation: When drift trips at depth 0, wakes decompose-prompt.md to split into 2–3 smaller slices via local_tracker.py split. At depth 1, escalates cleanly to ready-for-human.
  • Container isolation: Pre-baked sandcastle:python-codex Docker image with /opt/venv symlinked into /usr/local/bin and read-only ~/.codex/auth.json mount.

8. Frozen /grill-me Spec Contracts & End-of-Goal Audit

Saves your agreed /grill-me decisions as numbered REQ-*, INV-*, and OUT-* items. When a Goal completes, a fresh Spec Auditor maps each item to code and a test — and TypeScript cross-checks every cited test against real pytest -v output.

Why it matters: Catches cross-slice drift, silently dropped requirements, scope creep, and hallucinated test names before you ever merge.
Technical Details — How Deterministic Cross-Verification Works
  • Step 1: Copy docs/specs/TEMPLATE.md to docs/specs/<slug>.md and set "specFile" in goal.json.
  • Step 2: At Goal completion, goal.ts runs pytest -v to collect exact passing test IDs and runs 1 fresh-context audit against git diff <startCommit>..HEAD.
  • Step 3 (100% deterministic TypeScript): The auditor never picks a score or badge. verifySpecAuditAgainstTests() checks that:
    • Every REQ-* / INV-* / OUT-* ID appears (omitted IDs become MISSING → hard block).
    • Every VERIFIED row cites a test that literally passed in pytest -v (fake/unrun tests are downgraded automatically).
    • Cited files actually exist on disk.

9. Overnight Architecture Bot (1–2 High-ROI Proposals/Night)

Scans git commit history to find the files you actually touch most (high-churn hotspots) and proposes 1–2 deep-module refactoring improvements overnight — never touching stable, untouched code.

npm --prefix .sandcastle run nightly-arch -- --mode tickets
Technical Details — Two Safe Modes (Tickets vs. Draft Branch)
  • Default --mode tickets (safest): Zero source edits. Writes 1–2 proposals as needs-triage tickets in .scratch/ plus a styled PM HTML report. You promote only the winners to ready-for-agent.
  • Optional --mode draft-branch: Builds each proposal on an isolated arch-bot/YYYY-MM-DD-<slug> branch and discards any branch that fails python scripts/check.py.
  • Churn ranking: Deterministic git-log analyzer ranks Python files under src/ by recent touch frequency so the bot focuses strictly on active pain points.

10. Parallel Prototype Bake-Off (3 Competing Architectures)

Automates Matt's "Prototype / Design It Twice" workflow: forks 3 competing design variants in parallel Docker branches, scores each deterministically on 6 gates + mutation kill + brevity, and lets a fresh Adversarial Judge pick the winner or best hybrid.

npm --prefix .sandcastle run bakeoff -- --slug parser-v2 --brief "Extract parser"
Technical Details — 3 Variant Personas & Deterministic Ranking
  • Shared exploration via parent.fork(): One read-only Scout explores the repo once, then forks 3 isolated builders:
    • Variant A: Minimal Deep Module (tiny surface area, fewest moving parts)
    • Variant B: Explicit Pipeline / Data-Flow (clear typed stages)
    • Variant C: Strict Boundary / Extensible Strategy (plug-in adapters)
  • Deterministic score formula: Rewards passing all 6 gates, higher coverage & mutation kill %, and penalizes bloated diffs.
  • Never auto-merges: Outputs branches + comparison report + PM HTML/Jira summary so you pick the winning architecture deliberately.

11. Deterministic Confidence Grading (0–100 + Action Badges)

Replaces unreliable LLM self-ratings with exact TypeScript math and strict hard caps so a high lint score can never hide a test-tamper attempt, drift split, or missing spec item.

90–100 · Spot-Check Ready
Clean 6-gate pass, 90%+ mutation, 0 tampering, 0 drift, spec verified.
75–89 · Quick Review
All gates green with light friction (e.g., 1 review fix round).
50–74 · Review Carefully
Hard-capped due to tamper attempt, drift split, scope creep, or huge diff.
0–49 · Blocked — Do Not Ship
Failed gate, missing spec item, or unresolved Standards violation.
Technical Details — Hard Cap & Deduction Table
  • Hard Blocks (Blocked — Do Not Ship): Failed check.py or escalated slice (cap 35), any missing spec item (cap 40), any unresolved Standards violation (cap 45).
  • Risk Caps (Review Carefully): Recovered test_guard tamper block (cap 65), violated OUT-* non-goal (cap 68), hallucinated cited test (cap 70), mutation < 85% (cap 70), drift split or scope creep (cap 72), diff > 400 lines (cap 74).
  • Deductions: Mutation 85–89% (-5), coverage < 95% (-8), adversarial fix rounds (-6 each, max -18), diff 251–400 lines (-4), context > 75% (-8).
  • Factory blend: Overall factory score blends 60% average slice + 40% worst slice so a single weak slice always stands out.

12. Agent Trust Score, Human Reality Check & Parameter Tuner

Tracks rolling trust across your verified local runs + optional 5-second post-review ratings (good / tweak / rework), tells you which Autonomy Tier your harness has earned, and unlocks safety-clamped parameter tuning after 10+ verified runs.

npm --prefix .sandcastle run trust
Technical Details — Autonomy Tiers, 10-Run Lock & Safety Clamps
  • 5 Trust Dimensions (rolling last 20 verified runs): Integrity Rate (zero tamper attempts), Delivery Rate, First-Pass Rate, Stability Rate (zero drift/escalation), and Human Approval Rate (good=100%, tweak=60%, rework=0%).
  • Autonomy Readiness Tiers:
    • Supervised Only: < 10 verified runs, trust < 70, or integrity < 95%.
    • Factory Ready (Level 1): >= 10 runs, trust 70–84, integrity >= 95%.
    • Goal Autonomy Ready (Level 2): >= 10 runs, trust >= 85, integrity >= 98%, and human approval >= 85% (if rated).
  • Diagnostic Lever: Automatically pinpoints the single lowest dimension and tells you which harness control to tighten (specs, slice size, fixtures, or prompts).
  • Parameter Tuner (npm --prefix .sandcastle run tune): Hard-blocked until >= 10 local .sandcastle/logs/runs/*.json files physically exist and parse validly; read-only proposals clamped inside strict numeric bounds; ingests your rate --note feedback automatically.

14. Legacy Refactoring Playbook, Easy-to-Change Guide & Readiness Check

Tells you how to safely modernize multi-thousand-line patched scripts without a risky rewrite — using the Strangler Fig pattern, anonymized golden fixtures, monotonic ratchets, and a binary 5-layer readiness verifier.

Technical Details — 4-Step Legacy Modernization Sequence
  • Step 1 (Snapshot baseline): Run python scripts/ratchet.py --init once to freeze existing debt without fixing 1,000 old lines upfront.
  • Step 2 (Pin behavior before refactoring): Capture anonymized JSON golden fixtures + public-seam replay tests + 1 Hypothesis invariant.
  • Step 3 (Strangle incrementally): Extract one pure deep module per vertical slice; let import-linter + test_guard.py + mutation_check.py prevent regressions.
  • Step 4 (Compound cleanliness): Keep high-churn hotspots clean with nightly-arch and shrink debt monotonically on every PR via ratchet.py --shrink.

16. Anonymized Upstream Issue Reporter (Issue-Only, Human-Approved)

Report workflow bugs or improvement ideas back to the template repo safely — captures only sanitized environment/harness details (never work code or patches), scrubs all PII/paths/internal terms, previews locally first, and requires explicit human PUBLISH confirmation.

python scripts/upstream_report.py --kind bug --title "Short title" --summary "What happened"
Technical Details — 4-Layer Privacy Firewall & Local Blocklist
  • Issue-Only Scope: Never exports code diffs or work files. Optional --cmd only permits allowlisted harness scripts and replaces any traceback frame outside scripts/ or .sandcastle/ with <work-repo-frame>.
  • Deterministic Anonymizer + Local Blocklist: Strips usernames, hostnames, home/repo paths, emails, IPs, internal URLs, ticket IDs, UUIDs, tokens, and any custom company/product terms listed in gitignored .sandcastle/redact-terms.local.txt.
  • Two-Step Human Approval: Defaults to dry-run (saves .sandcastle/logs/upstream-issue-draft.md); --publish hard-blocks on any residual secret and requires typing PUBLISH verbatim before calling gh issue create.
